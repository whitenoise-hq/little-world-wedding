# 기획: 리틀 월드 웨딩

게임처럼 캐릭터를 움직이며 둘러보는 픽셀아트 모바일 청첩장이다. 화면 구조와 기능은 하나로 두고, 무대(테마)만 골라 쓴다. 커플마다 데이터를 넣어 각자 고유한 주소를 준다.

- 참고한 청첩장: https://our-little-wedding.vercel.app/village/ (코드나 그림은 가져다 쓰지 않고 구조만 참고)
- 목업: [우주 테마](mockup/index.html), [마을 테마](mockup/village.html). 브라우저로 열면 바로 움직여 볼 수 있다. 화면 왼쪽 위 버튼으로 테마를 오간다.
- 목업은 방향을 잡기 위한 시안이다. 세부는 구현하면서 조정하고, 바뀐 결정은 이 문서에 먼저 반영한다.

## 1. 서비스 구조

```
{도메인}/admin     → 어드민 (청첩장 생성·수정, 운영자 1명만 사용)
{도메인}/{slug}    → 커플별 청첩장
```

| 항목 | 결정 |
|---|---|
| 프레임워크 | Next.js. `/[slug]` 동적 라우트 하나로 모든 청첩장 처리 |
| DB·저장소 | Supabase (DB, 사진 스토리지, 어드민 로그인) |
| 게임 화면 | 2D 캔버스 픽셀아트. 무거운 엔진(three.js 등) 없이 가볍게 |
| 어드민 | 운영자만 관리. 신랑·신부 로그인 없음 |
| 배포 | Vercel |

### slug 규칙

- 영어 소문자 8자리 무작위 문자열 (예: `/ejdushfe`). 경우의 수 약 2,090억(26⁸)이라 추측해서 찾기 어렵다.
- 대소문자를 섞지 않는다. 카톡·문자로 전달하거나 손으로 칠 때 헷갈리지 않게 하려는 것이다.
- `crypto.getRandomValues`로 생성한다. `Math.random`은 쓰지 않는다.
- 256은 26으로 나누어떨어지지 않으므로, 234 이상인 바이트는 버리고 다시 뽑는다(모든 글자가 같은 확률로 나오게).
- DB에 unique 제약을 걸고, 겹치면 다시 생성한다.
- 어드민에 "주소 다시 만들기" 버튼을 둔다. 링크가 원치 않는 곳에 퍼졌을 때 쓴다.
- 검색에 노출되지 않게 `noindex`를 건다.

```ts
const ALPHABET = 'abcdefghijklmnopqrstuvwxyz'
const SLUG_LENGTH = 8
const LIMIT = 256 - (256 % ALPHABET.length) // 234

export function generateSlug(): string {
  let slug = ''
  while (slug.length < SLUG_LENGTH) {
    for (const b of crypto.getRandomValues(new Uint8Array(SLUG_LENGTH))) {
      if (b < LIMIT && slug.length < SLUG_LENGTH) slug += ALPHABET[b % ALPHABET.length]
    }
  }
  return slug
}
```

## 2. 테마

모든 테마는 같은 규칙을 따른다. 장소 3곳(집·사진·방명록), 같은 모달 내용, 같은 조작, 같은 캐릭터를 쓰고 그림과 방명록 연출만 다르다. 어드민에서 청첩장마다 테마를 하나 고른다.

### 공통 그림 규칙

- **화면 배율:** 저해상도(114×227)로 그린 뒤 3배 확대해 픽셀을 또렷하게 보여준다. 월드(200×340)가 화면보다 크고, 카메라가 캐릭터를 따라 상하좌우로 움직인다.
- **그림 스타일:** 색 수를 제한한 팔레트, 디더링 음영, 모든 물체에 어두운 외곽선(`#2a1a2e`). 픽셀 폰트는 갈무리(Galmuri11).
- **겹침 순서:** 물체를 발밑 y좌표 순으로 그려서 캐릭터가 물체 앞뒤로 자연스럽게 지나간다.
- **방명록 오브젝트:** 글 하나가 오브젝트(별·물고기) 하나다. 위치·색·움직임은 글 id의 해시로 정해서 다시 들어와도 같다. 탭하면 이름과 글이 말풍선으로 뜬다.

### 테마 비교

| | 우주 (`space`) | 마을 (`village`) |
|---|---|---|
| 무대 | 마션풍 붉은 행성(원형). 아래로 우주가 펼쳐짐 | 숲으로 둘러싸인 마을. 아래로 해변과 바다 |
| 이동 범위 | 행성 가장자리 안쪽 | 숲 안쪽 육지 + 부두 (바다는 부두로만 들어감) |
| 집 | 컨테이너형 거주 모듈 (태양광 패널, 안테나, 둥근 창, 착륙 다리) | 빨간 지붕 집 (굴뚝 연기, 하트 장식 문, 창가 화분, 우체통) |
| 사진 | 투명 돔 온실 (해바라기, 토마토 덩굴, 꽃 화단) | 분홍 줄무늬 정자 (안에 사진이 걸려 있음, 옆에 삼각대 카메라) |

| 오브젝트 보이는 조건 | 항상 보임 | 멀리서는 그림자, 해변·부두에 가까이 가면 색이 보임 |
| 시작 위치 | 행성 가운데 | 웨딩 입구 바로 앞. 처음 들어오면 신랑·신부 바로 뒤에 입구가 보임 |
| 고정 장식 | 탐사 로버, 위성 안테나, 하트 깃발, 크리스탈, 빛나는 외계 식물, 연못, 크레이터 | 웨딩 입구(하트 장식 꽃 아치, 흰 천), 입구부터 이어진 흰 버진로드, 버진로드 끝의 작은 분수, 나무, 꽃밭, 가로등, 표지판, 나룻배, 등대 |
| 움직이는 장식 | 줄전구, UFO, 별똥별, 반짝이는 별, 안테나 불빛 | 줄전구, 분수 물줄기, 분수 주위를 뛰어다니다 가끔 앉는 흰 강아지, 해변을 오가는 거북이, 굴뚝 연기, 나비, 갈매기, 파도 거품, 물결 반짝임, 등대 불빛, 카메라 플래시 |
| 모달 헤더 색 | `#2a2450` (밤하늘 남색) | `#1e4660` (바다 남색) |

새 테마를 추가할 때는 위 표의 칸을 모두 채우고, 이동 범위와 자동 이동 경로(6장)를 함께 정한다.

## 3. 첫 화면 (인트로)

접속하면 게임 화면 위에 전체화면 인트로를 먼저 띄우고, 그 뒤에서 게임을 불러온다. 로딩 화면을 기다림이 아니라 청첩장 표지처럼 쓰는 것이 목적이다.

- **내용:** 신랑·신부 이름(`원재 ♥ 은빈`), 날짜·시간, 짧은 문구 한 줄(예: "저희 결혼합니다", 어드민에서 수정). 테마 색 배경에 픽셀 장식을 살짝 넣고, 캐릭터 둘이 제자리에서 걷는 작은 애니메이션을 둔다.
- **로딩 표시:** 문구 아래에 픽셀 칸이 하나씩 차는 진행 막대를 둔다. 기준은 게임 코드, 폰트, 첫 화면 그림 준비다. 사진은 기다리지 않는다.
- **들어가기:** 준비가 끝나면 진행 막대가 "들어가기" 버튼으로 바뀐다. 누르면 인트로가 위로 걷히거나 픽셀 단위로 사라지며 게임 화면이 나온다.
  - 자동으로 넘기지 않고 한 번 누르게 한다. 표지를 읽을 시간을 주고, 이 터치로 브라우저의 소리 재생 제한이 풀려서 배경음악을 켤 수 있게 된다.
  - 빨리 불러왔으면 버튼이 바로 보인다. 일부러 기다리게 하지 않는다.
- **서버에서 바로 그린다:** 인트로는 `/[slug]`에서 서버가 HTML로 바로 보내는 화면이다. 게임 코드·사진과 관계없이 첫 화면이 즉시 뜬다. 폰트가 늦으면 시스템 폰트로 먼저 보여준다.
- **다시 방문:** 같은 기기에서 다시 들어오면(로컬 저장) 인트로를 짧게 보여주거나 바로 버튼 상태로 시작한다.
- "조이스틱이나 버튼으로 움직여 보세요" 안내는 인트로를 지나 게임 화면에 처음 들어왔을 때 띄운다.

## 4. 장소와 모달

| 장소 | 모달 제목 | 모달 내용 |
|---|---|---|
| 집 | 집 | 인사말, 일시, 장소, 오시는 길, 연락처, 계좌 (한 모달에 스크롤) |
| 사진 | 테마별 (온실 · 사진 / 정원 · 사진) | 사진 갤러리 |
| 방명록 | 테마별 (망원경 · 방명록 / 낚시터 · 방명록) | 방명록 쓰기·목록 |

- 장소 가까이 가면 "{장소} 들어가기" 버튼이 뜬다 (예: 집 들어가기, 낚시터 들어가기).
- "우리 집"이라는 이름은 쓰지 않는다. 버튼·모달·안내 모두 "집"으로 통일한다.

### 집 모달 (위에서 아래로)

1. **인사말:** 인사말 글, 양가 부모님 성함과 신랑·신부 이름
2. **예식 일시:** 날짜·요일·시간, 달력(해당 날짜 표시), D-day
3. **예식 장소:** 예식장 이름·홀, 주소(복사 버튼), 카카오맵, 길찾기 버튼(카카오맵, 네이버지도, 티맵)
4. **오시는 길:** 지하철, 버스, 주차, 기타 안내 (어드민에서 항목 추가)
5. **연락하기:** 왼쪽 신랑, 오른쪽 신부 두 열. 이름과 전화·문자 아이콘. "혼주에게 연락하기"를 펼치면 양가 아버지·어머니 연락처가 나온다.
6. **마음 전하실 곳:** 신랑 측 / 신부 측 아코디언. 사람마다 은행, 계좌번호, 예금주, 복사 버튼. 카카오페이 송금 버튼은 선택.

### 모달 디자인

- 화면 가운데에 떠 있는 패널로, 사방 5%씩 띄워 **화면의 90%** 를 채운다.
- 어두운 외곽선 3px과 깎인 모서리로 픽셀 느낌을 낸다. 열 때 살짝 커지며 나타난다(4단계로 끊어지는 애니메이션).
- 헤더는 테마 색 배경에 장소 아이콘과 제목, 오른쪽에 네모난 닫기 버튼을 둔다. 헤더 아래에 노란 강조선을 넣는다.
- 본문만 스크롤한다. 스크롤바는 테마 색 막대에 어두운 외곽선을 두른 픽셀 스타일이다(Chrome·Safari는 `::-webkit-scrollbar`, Firefox는 `scrollbar-color`로 대체).
- 닫기 버튼이나 바깥 어두운 영역을 누르면 닫힌다.

### 사진 모달

- 모든 사진을 **가로 3칸 격자**로 쭉 나열한다. 정사각형 썸네일에 번호를 작게 표시한다.
- 썸네일을 누르면 **전체화면 보기**가 뜬다. 위쪽에 `06 / 12` 번호와 닫기 버튼, 가운데 큰 사진, 아래에 사진별 한 줄 설명과 이전·다음 버튼을 둔다.
- 전체화면에서 사진을 좌우로 밀어서(스와이프) 넘길 수 있고, 처음과 끝은 이어진다.
- 어드민 사진 항목에 사진마다 한 줄 설명(선택)을 추가한다.

## 5. 방명록

- 입력: **이름, 메시지** 두 가지만 받는다. 비밀번호는 받지 않는다.
- **한 번 남긴 글은 작성자가 수정하거나 지울 수 없다.** 입력 폼 아래에 "남긴 글은 수정하거나 지울 수 없어요"라고 알린다.
- 글을 남기면 모달이 닫히고, 카메라가 방명록 영역으로 잠시 이동해 새 오브젝트가 생기는 연출을 보여준다. 새 오브젝트는 한동안 강조 표시(별은 크게, 물고기는 머리 위 하트)를 한다.
- 모달 안에는 전체 글 목록도 같이 보여준다.
- 운영자는 어드민에서 어떤 글이든 삭제할 수 있다. 작성자가 지울 수 없으므로 운영자 삭제가 유일한 정리 수단이다.
- 스팸 방지 대책이 필요하다. 같은 기기·IP의 연속 작성 제한, 글자 수 제한(이름 12자, 메시지 120자)을 기본으로 둔다.

## 6. 캐릭터와 조작

### 캐릭터

- 7×11 도트의 신랑·신부. 신랑은 항상 왼쪽, 신부는 항상 오른쪽에 붙어서 걷는다. 이동 방향에 따라 좌우로 돌아보기만 하고 자리는 바뀌지 않는다.
- 머리 위에 이름표 하나: `원재 ♥ 은빈` (가운데 하트)
- 걸을 때 다리가 움직이고 몸이 살짝 들썩인다.
- 나중에 어드민에서 헤어스타일과 옷 색을 고를 수 있게 한다 (둘을 닮게 만드는 것이 핵심).

### 조작

| 요소 | 위치 | 동작 |
|---|---|---|
| 조이스틱 | 왼쪽 아래, 고정형 | 미는 방향과 세기만큼 걷기. 가운데 작은 데드존. 상하좌우에 픽셀 화살표가 있고, 미는 방향의 화살표가 강조색으로 켜진다 |
| 플로팅 버튼 3개 (집, 사진, 방명록) | 오른쪽 아래 | 누르면 해당 장소까지 자동으로 걸어감. 조이스틱을 만지면 자동 이동 취소 |
| 들어가기 | 가운데 아래쪽 | 장소 가까이 가면 뜸. 누르면 모달 열림 |
| 키보드 (PC) | - | 방향키·WASD 이동, E 키로 들어가기 |

- 자동 이동은 직선으로 걷는다. 마을 테마처럼 바다로 막힌 곳이 있으면 경유지(부두 입구)를 거친다. 막혀서 움직이지 못하면 자동 이동을 멈춘다.

### 모바일 웹에서 챙길 것

- 조이스틱 조작 중 페이지 스크롤·확대 막기 (`touch-action: none`)
- 카톡 인앱 브라우저의 왼쪽 끝 스와이프(뒤로 가기)와 겹치지 않게 가장자리에서 띄우기
- 아이폰 하단 홈 바와 겹치지 않게 safe-area 반영
- 처음 들어오면 "조이스틱이나 버튼으로 움직여 보세요" 안내를 한 번 띄움

## 7. 어드민 입력 항목 (청첩장 1건)

| 구분 | 항목 |
|---|---|
| 기본 | slug(자동 생성, 재발급), 공개/비공개 |
| 테마 | 우주 / 마을 중 선택 |
| 인물 | 신랑·신부 이름, 양가 부모님 성함 |
| 인트로 | 인트로 문구 한 줄 (기본값 있음) |
| 인사말 | 인사말 글 |
| 예식 | 날짜·시간, 예식장 이름, 홀, 주소, 좌표, 교통 안내 |
| 연락처 | 신랑, 신부, 양가 부모님 전화번호. 사람마다 노출 여부 |
| 계좌 | 신랑 측·신부 측 계좌 목록. 사람마다 노출 여부, 카카오페이 링크(선택) |
| 사진 | 사진 여러 장(순서 변경, 사진별 한 줄 설명), 카톡 공유용 대표 사진 |
| 꾸미기 | 캐릭터 헤어·옷 색, 배경음악 |
| 방명록 | 글 목록, 삭제 (운영자만) |

## 8. 꼭 챙길 것

1. **카톡 공유 미리보기:** 청첩장마다 OG 태그(제목, 설명, 대표 사진)를 다르게 생성한다. 가장 중요하다. `/[slug]`의 `generateMetadata`로 처리하므로 1단계에서 함께 만든다.
2. **사진 최적화:** 업로드할 때 리사이즈·압축한다.
3. **배경음악:** 꺼진 상태로 시작한다.
4. **저작권:** 그림·폰트·음악은 상업적 이용이 가능한 것만 쓴다. 갈무리 폰트는 OFL이다.
5. **로딩·성능:** 픽셀을 코드로 그리는 비용은 작다. 목업 측정 기준 첫 화면 준비 약 20ms, 프레임당 약 0.5ms(데스크톱)이다. 무거운 것은 외부 파일과 사진이다(목업 기준 아이콘 폰트 865KB, 갈무리 폰트 505KB).
   - **아이콘:** 아이콘 폰트를 쓰지 않는다. 실제로 쓰는 아이콘(약 15개)만 SVG로 넣는다.
   - **폰트:** 갈무리에서 필요한 글자(한글 상용 2,350자, 영문, 숫자, 기호)만 남긴 서브셋을 직접 호스팅한다(목표 150KB 이하). `font-display: swap`을 쓰고 미리 불러온다(`preload`).
   - **사진:** 업로드할 때 격자용 썸네일과 전체화면용 큰 사진을 따로 만든다(WebP/AVIF). 썸네일은 사진 모달을 열 때, 큰 사진은 누를 때 불러온다. 다음·이전 사진은 미리 불러온다.
   - **게임 코드:** 게임 화면은 별도 청크로 나눠 인트로가 떠 있는 동안 불러온다. 배경처럼 움직이지 않는 그림은 처음 한 번만 그려 두고, 매 프레임에는 움직이는 것만 다시 그린다.
   - **배터리:** 모달이나 전체화면 사진이 열려 있거나 앱이 백그라운드로 가면(`visibilitychange`) 그리기 루프를 멈춘다. 30fps로 제한한다.
   - **목표:** 모바일 데이터로 카톡 인앱 브라우저에서 열었을 때 인트로가 1초 안에 뜨고, 3초 안에 들어갈 수 있다. 실제 폰(저사양 안드로이드 포함)에서 측정한다.

## 9. 진행 순서

1. 데이터 구조, 어드민, `/[slug]` 페이지 (게임 없이 일반 청첩장 형태) + OG 태그 + 인트로 화면
2. 픽셀아트 게임 화면을 붙이고 장소와 데이터 연결. 엔진(렌더러, 입력, 카메라, 충돌)과 테마(그림, 장소 좌표, 이동 범위, 방명록 연출)를 분리해 테마를 갈아끼울 수 있게 만든다
3. 방명록 관리·스팸 방지, 사진 최적화, 로딩·성능 측정과 개선

## 10. 아직 정하지 않은 것

- 참석 여부 받기(RSVP)를 넣을지, 넣는다면 어디에 둘지
- 인트로의 "들어가기" 버튼을 "음악과 함께 들어가기 / 조용히 들어가기" 두 개로 나눌지
- 게임 없이 세로로 한 번에 보는 "바로 보기" 화면을 둘지
- 그림을 직접 그린 픽셀아트로 계속 갈지, 캐릭터만 외주나 구매 소스로 바꿀지
- 테마를 더 늘릴지 (늘린다면 2장 표의 칸을 채우는 것부터)
